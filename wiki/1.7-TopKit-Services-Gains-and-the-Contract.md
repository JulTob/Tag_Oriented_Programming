# Services, Gains, and the Contract

> **Vocabulary proposal.** This page records the Director's current language
> for review. It does not change the deployed runtime or clear a STEP.

Preconditions and Postconditions may calculate similar boolean answers, but
they do different work and live in different places.

The short version is:

> A **Precondition is a Service of the Tag**. A **Postcondition is a Gain of
> the Agent**. The living bond made from the Agent's Posts is **the
> Contract**.

## The vocabulary

| Word | TOP meaning |
| --- | --- |
| **Feature** | A named thing exposed by an Agent or a Tag. It is the broad author-facing word; Action, Record, Post, Report and Operation remain the precise kinds. |
| **Service** | Work or information owned by a Tag. A Pre is an admission Service: the Tag uses it while deciding whether a Target may be tagged. Reports and Operations are continuing Tag Services. |
| **Gain** | Something a Tag applies to one Agent. Actions, Records and applied Posts are Gains. |
| **Contract** | The live bond between an Agent and its Agencies, composed from the Posts the Agent currently carries. It determines whether that Agent is valid or broken. |

`Contribution` remains useful as the implementation word for one declared
Overlay layer. These ownership words answer a different question: who serves
it, who gains it, and what relationship does it establish?

## A Pre is a Service

```python
class Guild(Tag):

    @Pre
    def Has_Invitation(target):
        return target.invited
```

`Has_Invitation` belongs to `Guild`. The Guild consults that Service before
Tagging. It does not give `Has_Invitation` to the Target, and it does not need
to store a copy on a refused or admitted Agent.

This is why a Pre cannot be crushed by an Agent Feature with the same name.
There is no Pre layer on the Agent to crush. The Service is consulted for a
Tagging attempt and then that consultation is over.

## A Post is a Gain

```python
class Guild(Tag):

    @Post
    def Keeps_Oath(agent):
        return agent.oath_is_kept
```

The declaration is written by `Guild`, because the Guild states the
responsibility. When Guild admits Ari, Ari gains that Post layer. The Post can
then be read and composed at Agent scope, and it participates in
`bool(ari)`.

Both descriptions are therefore true:

- the Tag authors and names the responsibility;
- the Agent carries the applied Post as a Gain.

Field membership ties those two sides together. Under the current design
direction, an ordinary Post Gain ends when that Tag application leaves its
Field. A `@Constant @Post` is the explicit exception: it remains an
uncrushable responsibility after the membership ends.

## The Contract is the bond

The Contract is not a third kind of callable and it is not another container
beside the Agent. It is the relationship formed by the Agent's live Post
Gains.

An adventurer may answer to several guilds; an Agent may belong to several
Agencies. Each Tagging can add its own Posts, and those Posts Overlay on the
Agent. Together they form the Agent's Contract:

- every visible Post holding means a valid Agent;
- any visible Post failing means a broken Agent;
- no Posts means no broken promise, so the Contract holds;
- an arrested Agent is a separate Safehouse state while Rip work remains.

This preserves both scopes without pretending that Tags share a Field or
inherit one another. Each Tag owns its declaration and its membership. The
Agent carries the resulting responsibilities together.

## The same calculation may serve twice

```python
class Guild(Tag):

    @Pre
    @Post
    def Keeps_Oath(agent):
        return agent.oath_is_kept
```

This spelling may reuse one calculation, but it establishes two independent
roles:

1. the Pre Service is consulted before Tagging;
2. the Post Gain is applied through the successful Tagging and joins the
   Agent's Contract.

Ending or deleting the Post Gain does not alter the Guild's Pre Service.
There is no same-name pile joining the two.

## Reading the model

Use these questions when a design becomes unclear:

- **Who owns the work before Tagging?** The Tag serves the Pre.
- **What did this Agent receive?** The Agent gained the Post.
- **What ties the Agent to its Agencies now?** Its Contract.
- **Does one Tag imply another Tag's Field or Posts?** No. Any layering or
  redirection must be explicit.

This vocabulary leaves the familiar TOP syntax intact while making the
lifetimes and ownership visible in ordinary language.
