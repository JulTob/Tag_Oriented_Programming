# Link underlays: ordered Taggings before a Link

> **Proposal only.** This page records a design under review. Released
> TopKit does not provide this syntax or behavior yet. The proposal belongs
> to STEP-SPEC-52. Its revised modifier spelling is under review in
> [PR #395](https://github.com/JulTob/Tag_Oriented_Programming/pull/395); the
> [earlier Brief](../steps/spec/STEP-SPEC-52-ordered-link-bases.md) records a
> class-base sketch that this revision sets aside.

A Link may need its Contact to finish other Taggings before the selected
Link begins. A trusted Contact may first need the ordinary `Network` Tag,
the Link Agent's own `Knows` Link, and a particular server's `Registre`
Link. These are **underlays** because their complete Taggings happen first.

The proposed spelling is:

```text
@Link(underlays=(Network, Agent.Knows, server.Registre))
class Trusts(Tag):
    ...
```

The modifier and its runtime behavior remain provisional. The owner/self
selector word is settled: **`Agent.Knows`** names the actual `Knows` Link of
the Agent whose selected Link is being called. The three forms are distinct:

| Underlay | Tagging performed for `ari.Trusts(ruth)` |
| --- | --- |
| `Network` | The ordinary Tagging `Network(ruth)` |
| `Agent.Knows` | The owner-relative actual Link Tagging `ari.Knows(ruth)` |
| `server.Registre` | The exact external Agent Link Tagging `server.Registre(ruth)` |

`Agent.Knows` is resolved when Ari makes the call. If Ben calls
`ben.Trusts(ruth)`, the same selector resolves to `ben.Knows`. An exact
external selector keeps the Agent coordinate too: every call resolves the
current `server.Registre`, rather than copying the Link that happened to be
visible when `Trusts` was declared. The proposed soft coordinate does not
keep the external Agent alive.

## Complete turns, in written order

For `ari.Trusts(ruth)`, the proposal runs:

```text
Network(ruth)
ari.Knows(ruth)
server.Registre(ruth)
ari.Trusts(ruth)
```

Each line is a complete, ordinary Tagging. Its Gate, Gainings, Imprints,
Field admission, Posts, diagnostics, and recovery rules finish before TOP
starts the next line. A failure stops the sequence where it lands. A
previously completed Tagging remains completed; the selected `Trusts` Link
has not started if an underlay stops first.

The selected Link is last. Its own Pair training never absorbs a prior
turn merely because that turn was named as an underlay.

An already-admitted Contact follows the ordinary active-Tag rule. Calling
`ari.Trusts(ruth)` again is a no-op, even if the Relation has gained another
underlay since Ruth entered the Link. The call does not partly update the
old Pair or silently run the new underlay. Rip and link again to request the
current sequence explicitly:

```text
del ari.Trusts[ruth]
ari.Trusts(ruth)
```

## A Relation is a blueprint

Bare `Knows` is not a valid underlay. A Relation declaration is the
blueprint used to make actual Links; it has no Contact Field and is not a
Tag that can receive Ruth. The program must identify an actual Link:

- `Agent.Knows` means the current Link Agent's actual `Knows` Link;
- `server.Registre` means the actual `Registre` Link belonging to that
  particular external Agent.

This is why `@Link(underlays=(Network, Knows))` is not the proposal. It is
missing the Agent whose `Knows` Link TOP must call.

## Orthogonal Fields and Pairs

Underlay means ordered application, not shared storage. `Network`,
`ari.Knows`, `server.Registre`, and `ari.Trusts` keep separate Fields,
Gates, Posts, Rip protocols, and histories. The three actual Links keep
separate Pairs for Ari or the server and Ruth. Ripping one Link does not
remove Ruth from another.

If the selected Link needs a reciprocal Link such as `ruth.Knows(ari)`, its
Imprint must request that act explicitly. Nothing in the underlay list
implies a reciprocal Link or merges two Relations.

## Deployment boundary

Before this proposal can become deployed TOP, its STEP must settle:

- migration from the current Links draft, which uses Relation class bases.

Until then, use explicit calls where Links are available and treat every
example on this page as design notation rather than runnable TopKit code.
