# Tools: what an Agent has

`charlie.weapon` reads **"Charlie's weapon"**: a thing Charlie *has*. A
Tag is what you **are** (*ser*). A Record is what you are **currently**
(*estar*). A Tool is what you **have** (*tener*): a Record whose value is
an Agent in its own right, with its own Tags, Field, promises, keywords
and secrets. The curse on the sword is the sword's.

> **Status.** Every ```python block on this page runs in order as one
> program, the `@Tool(Weapon)` mark included. The pattern is the kit's
> laws applied to a Record whose value is an Agent; the mark and its three
> laws are [STEP-SPEC-36](../steps/spec/STEP-SPEC-36-tools.md).

## A tool is an Agent of its own

The sword gets its own Tags. The Fighter gets a Record whose builder
forges the sword, Tags it in plain sight, and returns it.

```python
from TopKit import (Action, Constant, Contract, Flag, Keyword, Post, Pre,
                    Precondition, Record, Report, Rip, Secret, Tag,
                    TagCompositionError, Tool, Underlay)


class Character:
    def __init__(character, name):
        character.name = name


class Sword:
    def __init__(sword, name):
        sword.name = name


class Weapon(Tag):                      # what the tool IS

    @Record
    def damage(tool):                   # the tool is the Agent here
        return 6

    @Action
    def Swing(tool):
        return f"{tool.name} swings for {tool.damage}"

    @Post
    def Has_An_Edge(tool):              # the tool's own promise; `return`, not `assert`
        return tool.damage > 0


@Flag
class Cursed(Tag):                      # a word, and a Layer, on the tool only

    @Action
    @Underlay
    def Swing(tool, underlay):
        return underlay() + ", and the curse bites"


class Fighter(Tag):

    @Record
    def weapon(agent):                  # the forge
        sword = Sword(f"{agent.name}'s sword")
        Weapon(sword)                   # the tool is Tagged when gained, at Parts
        return sword

    @Post
    def Armed(agent):                   # the bearer's promise ABOUT its tool
        return ("weapon" @ agent
                and agent.weapon in Weapon[:]
                and Contract.Holds(agent.weapon))

    @Rip
    def Disarm(agent):                  # the promise ends with the Tag; the sword stays
        Contract.Delete(agent, "Armed")


charlie = Character("Charlie")
bob = Character("Bob")
Fighter(charlie)
Fighter(bob)

assert charlie.weapon in Weapon         # the tool is a Weapon
assert charlie not in Weapon            # the bearer is not
assert list(Weapon) == [charlie.weapon, bob.weapon]   # the Field holds swords, never bearers
assert charlie.weapon.Swing() == "Charlie's sword swings for 6"
```

The *uses* of a tool are its own Actions, reached through the name:
`charlie.weapon.Swing()`. The receiver is the sword. If a use needs the
bearer, pass the bearer: `agent.weapon.Swing(agent)`. The sword never
knows who holds it unless you write that down.

## The curse is the sword's

```python
Cursed(charlie.weapon)

assert charlie.weapon in Cursed         # membership is the sword's
assert charlie not in Cursed
assert "Cursed" in charlie.weapon       # the word is on the sword
assert not Keyword(charlie, "Cursed")   # and not on Charlie
assert charlie.weapon.Swing() == "Charlie's sword swings for 6, and the curse bites"
assert Contract.Holds(charlie)          # Charlie's promises hold: Armed asks for a sound Weapon, cursed or not
```

Ask the bearer with `Keyword(charlie, "Cursed")`. `"Cursed" in charlie`
is the host's own `in`, and a plain object with no Flag raises
`TypeError` on it; `Keyword` answers for every object.

The sword's Overlay is the sword's: `Cursed` extended `Weapon.Swing` on
the sword, and nothing on Charlie changed.

## Two truths

A tool keeps its own promises. `Contract.Holds(charlie.weapon)` asks the
sword; `Contract.Holds(charlie)` asks Charlie.

```python
assert Contract.Holds(charlie.weapon)

charlie.weapon.damage = 0               # the sword breaks its own promise
assert charlie.weapon in ~Weapon        # repair waits in the sword's Field
assert not Contract.Holds(charlie.weapon)
assert not Contract.Holds(charlie)      # only because Armed asked for a sound sword
assert charlie in ~Fighter

charlie.weapon.damage = 6               # repair the sword, and both hold again
assert Contract.Holds(charlie.weapon) and Contract.Holds(charlie)
```

This is where the truth of a *part* lives: on the part, as its own Post.
Nothing about the sword becomes a `__bool__` on Charlie. Charlie's
`Armed` is an ordinary, named promise, read at his boundaries and on
`bool(charlie)`, never continuously.

Two spellings to prefer:

- `Contract.Holds(agent.weapon)` rather than `bool(agent.weapon)` inside a
  Post. A host that defines its own `__bool__` keeps it on today's kit
  even once a Post is visible, so `bool` answers the host's question, not
  the contract's (#71 and #72 settle that rule). `Contract.Holds` asks
  the contract whatever the host says.
- `return tool.damage > 0` rather than `assert tool.damage > 0`. Python
  removes `assert` under `-O`, and an assert-only condition then holds
  vacuously.

## Hand-over, the empty hand, and the stick

A tool changes hands by assignment. The Tags travel because they are the
sword's. The empty hand is `del`.

```python
bob.weapon = charlie.weapon             # hand-over, line one
del charlie.weapon                      # hand-over, line two: Charlie drops it

assert not ("weapon" @ charlie)         # nothing in the slot
assert not Contract.Holds(charlie)      # Armed names what is missing
assert bob.weapon in Cursed             # the curse went with the sword

charlie.weapon = bob.weapon             # two bearers, one sword: allowed
assert charlie.weapon is bob.weapon
```

Here is the one place the pattern lies. A Record accepts any value, so a
stick is seated in silence, and only the promise notices, at the next
boundary or read:

```python
charlie.weapon = "a stick"              # accepted: a Record is a Record
assert not Contract.Holds(charlie)      # Armed: not a Weapon
assert charlie in ~Fighter

sword = Sword("Charlie's new sword")    # the repair: forge, Tag, then seat
Weapon(sword)
charlie.weapon = sword
assert Contract.Holds(charlie)
```

The `@Tool(Weapon)` mark refuses the stick at the write, with nothing
changed. See [The mark](#the-mark-toolweapon) at the end of this page.

## Reworking the tool in hand

A later Tag receives the held sword in the **stored seat** of its builder
and may improve it. Same object, better.

```python
class Enchanter(Tag):

    @Record
    def weapon(agent, stored):          # the stored seat holds the sword in hand
        stored.damage += 2
        return stored


before = bob.weapon
Enchanter(bob)
assert bob.weapon is before             # the same sword
assert bob.weapon.damage == 8           # sharper
```

A builder without the stored seat replaces the slot with a new sword; TOP
diagnoses that between independent Tags, as it does for any Record. To
keep the tool in hand when there may be none, test `stored is None`.
Never write `stored or forge()`: a defective tool is falsy, because its
truth is its contract, and `or` would quietly forge its replacement.

## A bonded tool

`@Constant` fixes the binding: no hand-over, no drop, kept across Rip.
The sword itself may still change, and may still be Cursed.

```python
class Oathbound(Tag):

    @Constant
    @Record
    def relic(agent):
        relic = Sword("the relic")
        Weapon(relic)
        return relic


Oathbound(bob)
try:
    bob.relic = Sword("a copy")
except TagCompositionError:
    pass
else:
    raise AssertionError("a bonded tool cannot be replaced")

Cursed(bob.relic)                       # Constant fixes the binding, not the sword
assert bob.relic in Cursed
```

## Two doors

Secrets stay behind the door of the Agent that owns them. Charlie's
Actions run inside Charlie's door and outside the sword's; the sword's
Actions, the other way round.

```python
class Vault(Tag):

    @Secret
    @Record
    def combination(tool):
        return "1234"

    @Action
    def Open(tool):
        return tool.combination         # inside the vault's door


class Guard(Tag):

    @Record
    def vault(agent):
        vault = Sword("the vault")
        Vault(vault)
        return vault

    @Action
    def Crack(agent):
        return agent.vault.combination  # outside the vault's door


ann = Character("Ann")
Guard(ann)
assert ann.vault.Open() == "1234"
try:
    ann.Crack()
except AttributeError:
    pass
else:
    raise AssertionError("a bearer never reads its tool's secrets")
```

Having the vault is not being inside it. A bearer uses what the tool
makes external. `@Secret` on the bearer's own slot
(`@Secret @Record def dagger`) hides the *slot* outside the bearer's
functions; the dagger object stays an ordinary Agent to anyone holding
it.

Two doors means two Agents' doors, exactly as the kit already opens
them; it is not an isolation between nested calls. A door stays open for
as long as its Agent's own function runs. So a tool's Action that the
bearer calls from inside its own Action, handing itself over
(`agent.weapon.Swing(agent)`), runs while Charlie's door is open and can
read Charlie's secrets through that reference, as any callback could.
The same Action called from outside Charlie's functions fails closed.

## Leaving

Rip never cascades, and Contributions are sticky. Rip the Fighter and
Charlie keeps the sword; his `Disarm` protocol ended the promise `Armed`
by name, because conditions are sticky too.

```python
del Fighter[charlie]

assert charlie not in Fighter
assert isinstance(charlie, Fighter)     # once a Fighter, always a Fighter
assert "weapon" @ charlie               # the sword stays in hand
assert Contract.Holds(charlie)          # Armed was ended in Disarm; nothing is promised
```

Rip the sword from `Weapon` and it stays in Bob's hand, a Rogue Weapon
with its sticky Actions. Bob's own promise notices.

```python
del Weapon[bob.weapon]

assert bob.weapon not in Weapon
assert isinstance(bob.weapon, Weapon)
assert not Contract.Holds(bob)          # Armed: not a Weapon now

Weapon(bob.weapon)                      # a fresh tagging repairs it
assert Contract.Holds(bob)
```

Deleting the bearer does not Rip the tool. The sword lives on wherever
else it is held: Excalibur outlives Arthur. A slot holds its tool
strongly, as a Record holds its value, which a Field never does.

## When the tool's own tagging fails

Tagging the sword inside the builder is a complete call on another
Target, with its own gate, Parts, Commit, Write and Quality check. Its
failure keeps its own name and refuses the bearer's Parts.

```python
class Holy(Tag):

    @Pre
    def Blessed_Steel(tool):
        return tool.name != "a stick"


class Crusader(Tag):

    @Record
    def weapon(agent):
        stick = Sword("a stick")
        Holy(stick)                     # refused at the stick's gate
        return stick


dan = Character("Dan")
try:
    Crusader(dan)
except Precondition.Blessed_Steel:
    pass
else:
    raise AssertionError("the sword's refusal must refuse the bearer")
assert dan not in Crusader              # the whole call rolled back
```

What the bearer's failure does **not** undo: a tagging that already
committed on the sword. If a later Record of the same call fails, the
sword stays a Weapon.

```python
kept = []


class Clumsy(Tag):

    @Record
    def weapon(agent):
        sword = Sword("the orphan")
        Weapon(sword)
        kept.append(sword)              # a name outside the call, to watch it
        return sword

    @Record
    def balance(agent):
        raise ValueError("dropped it")


try:
    Clumsy(dan)
except TagCompositionError:
    pass
assert dan not in Clumsy                # Dan did not enter Clumsy's Field
assert kept[0] in Weapon[:]             # the sword kept its Tag: two call boundaries
```

What happens to that sword next depends on the tagging sequence. On
today's kit the whole call rolls back: Dan does not hold the sword, and
once `kept` lets go of it nothing does, so it is collected and vanishes
from `Weapon`'s Field, because a Field never keeps an Agent alive. Under
the approved sequence (issue #30, STEP-SPEC-39, PR #78) Dan keeps the
sword as an acquired Gain, `dan.weapon`, and stands outside `Clumsy`'s
Field as a Rogue. Either way, a pre-existing object you handed in keeps
the Tag the forge applied. Rip is not restoration, and a forge cannot see
a later Record's failure, so there is no recipe inside the forge that
undoes it. If it matters, compensate on the calling side, tracking what
the call gained, and let the original failure stay the one that is
raised:

```python
loan = Sword("a loan")
was_a_weapon = loan in Weapon[:]


class Armed_With(Tag):

    @Record
    def weapon(agent, *, weapon):       # the tool comes in from the call
        Weapon(weapon)
        return weapon

    @Record
    def balance(agent):
        raise ValueError("dropped it")


try:
    Armed_With(dan, weapon=loan)
except TagCompositionError:
    if not was_a_weapon and loan in Weapon[:]:
        del Weapon[loan]                # the forge's act, undone by the same kind of act
    # then re-raise, in real code
assert loan not in Weapon               # the loan is as it was lent
```

## A shared tool

One tool for the whole Field is a Report. Its builder Tags the value the
same way; one object, held on the Tag.

```python
class Guild(Tag):

    @Report
    def engine(tag):
        engine = Sword("the siege engine")
        Weapon(engine)
        return engine


assert Guild.engine is Guild.engine
assert Guild.engine in Weapon
```

## The mark: `@Tool(Weapon)`

[STEP-SPEC-36](../steps/spec/STEP-SPEC-36-tools.md) adds one mark on a
Record builder, `@Tool(Weapon)`, with three laws: the slot holds a member
of the named Tags and never the bearer, checked when the slot is gained
and at every write; the slot is never `None` unless its kind says
`| None`, and `del` is the drop; the slot never Tags, the forge does. The
stick is then refused at the write, with nothing changed. `@Record` may
be written as well; it says nothing `@Tool` does not.

```python
class Knight(Tag):                      # the same forge, marked

    @Tool(Weapon)                       # a Record whose slot holds a Weapon
    def weapon(agent):
        sword = Sword(f"{agent.name}'s sword")
        Weapon(sword)                   # still in plain sight: the slot never Tags
        return sword


erin = Character("Erin")
Knight(erin)

try:
    erin.weapon = "a stick"             # refused: not a Weapon
except TagCompositionError:
    pass
assert erin.weapon in Weapon            # the slot is unchanged

try:
    erin.weapon = None                  # refused: this slot is never empty
except TagCompositionError:
    pass

try:
    erin.weapon = erin                  # refused: a Tool is never the bearer
except TagCompositionError:
    pass

del erin.weapon                         # the drop
assert not ("weapon" @ erin)            # so presence alone answers "armed?"


class Squire(Tag):

    @Tool(Weapon | None)                # the empty hand, declared where readers see it
    def weapon(agent):
        return None                     # admitted: the kind says so


finn = Character("Finn")
Squire(finn)
assert "weapon" @ finn                  # the slot exists
assert finn.weapon is None              # and is empty, by declaration
```

A kind of two Tags is written `@Tool(Weapon, Blessed)`: the slot holds a
member of both. `Weapon | None` is Python's own optional type;
`Weapon | Blessed` is the Field algebra ("sound in either"), and is
refused as a kind with the spelling meant. A later Tag may redeclare the
slot only as a Tool, with its own kind list, and receives the held tool
in its stored seat; a plain Record or an Action at that name is refused,
so the guard never goes away in silence. `@Delete` frees the slot.

```python
class Blessed(Tag):
    pass


class Paladin(Knight):

    @Tool(Weapon, Blessed)              # say everything the slot holds
    def weapon(agent, stored):          # the sword in hand, to bless
        Blessed(stored)
        return stored


gwen = Character("Gwen")
Paladin(gwen)
assert gwen.weapon in Weapon and gwen.weapon in Blessed

plain = Sword("a plain sword")
Weapon(plain)
try:
    gwen.weapon = plain                 # refused: a Weapon, but not Blessed
except TagCompositionError:
    pass
assert gwen.weapon in Blessed
```

Everything else on this page stays as it is: the barrier, the two doors,
two truths, hand-over by assignment, sticky slots, and the orphan.

## A Tool or a Link?

| | Tool | Link ([STEP-SPEC-22](../steps/spec/STEP-SPEC-22-links.md), Brief) |
| --- | --- | --- |
| What the Agent gets | one object it *has* | a Tag of its own: a category of others |
| Used with | the dot: `charlie.weapon.Swing()` | Ring 0 acts: `charlie.Knows(ruth)`, `ruth in charlie.Knows` |
| Seats of its functions | one, the tool | two, the Agent and the Contact |
| Reassigned | yes: hand-over is assignment | never: a held Link is read-only |
| Holds its thing | strongly, as a Record holds a value | weakly: a Field never keeps an Agent alive |
| When the Agent is deleted | the tool lives on wherever else it is held | the Link ends |
| What the held thing receives | nothing but its own Tags | membership, and Pair-scope members |

Both keep one direction and the barrier: nothing on the held thing names
the one who holds it.

## Reading a tool

| Question | On the bearer | On the tool's Tag |
| --- | --- | --- |
| Is there one? | `"weapon" @ charlie` | |
| Is it a Weapon, now? | `charlie.weapon in Weapon[:]` | |
| Is it sound? | `Contract.Holds(charlie.weapon)` | `for w in Weapon` walks the sound swords |
| Is it broken? | `charlie.weapon in ~Weapon` | `for w in ~Weapon` |
| Is it cursed? | `"Cursed" in charlie.weapon`, `charlie.weapon in Cursed` | `for w in Cursed` |
| Who bears a cursed one? | `[f for f in Fighter[:] if "weapon" @ f and f.weapon in Cursed]` | |

## Do and don't

- **Do** make a Tool for a thing with a being of its own. **Don't** make
  one for a number: that is a Record.
- **Do** Tag the tool in the forge, in plain sight. **Don't** expect
  assignment to Tag anything.
- **Do** promise about your tool in a named Post, with `return`.
  **Don't** write a dunder condition on the bearer.
- **Do** ask the tool's truth with `Contract.Holds(agent.weapon)`.
  **Don't** rely on `bool` when the host may define its own.
- **Do** drop with `del`, in a `@Rip` when leaving should disarm.
  **Don't** seat `None` as the empty hand.
- **Do** pass the bearer per use when a tool needs it. **Don't** store the
  bearer on the tool unless you mean the cycle.
- **Do** keep a tool in hand with `stored is None`. **Don't** write
  `stored or`: a defective tool is falsy.
