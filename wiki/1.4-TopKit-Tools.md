# Tools: what an Agent has

`charlie.weapon` reads “Charlie's weapon”: a thing Charlie **has**. A
Tool is an ordinary object held in a Record; it can also be an Agent
with its own Tags, Actions, Records and promises. The sword in this
guide is such an Agent. The curse on the sword is the sword's.

> **Status.** Every `python` block below runs on TopKit, in order, as
> one program, the admission modifier `@Tool` included. Its laws are
> [STEP-SPEC-36](https://github.com/JulTob/Tag_Oriented_Programming/pull/143)
> (Vetting). The approved Tagging sequence and Agent truth rulings have
> separate implementation PRs, identified where their behavior matters.

## Prepare the sword, then give it to the bearer

Forging and Tagging are acts. An Action or an Imprint performs them. A
Record builder reads the prepared value and returns it; it does not Tag,
Rip or improve another Agent.

A builder may construct a local initial value, just as it can return a
new list or record-object. Construction that performs training or other
world-facing effects belongs in an Action or Imprint. The prepared-value
pattern below makes that boundary explicit.

```python
from TopKit import (Action, Constant, Contract, Flag, Imprint, Keyword,
                    Post, Pre, Precondition, Record, Report, Rip, Secret,
                    Tag, TagCompositionError, Tool, Underlay)


class Character:
    def __init__(character, name):
        character.name = name


class Sword:
    def __init__(sword, name):
        sword.name = name


class Weapon(Tag):

    @Record
    def damage(tool):
        return 6

    @Post
    def Has_An_Edge(tool):
        return tool.damage > 0

    @Action
    def Swing(tool):
        if not tool:
            raise RuntimeError("the sword needs repair")
        return f"{tool.name} swings for {tool.damage}"


class Smith(Tag):

    @Action
    def Forge_Weapon(agent, name):
        sword = Sword(name)
        Weapon(sword)
        return sword


class Fighter(Tag):

    @Record
    def weapon(agent, *, weapon):
        return weapon

    @Post
    def Armed(agent):
        return ("weapon" @ agent
                and agent.weapon is not None
                and agent.weapon in Weapon[:]
                and bool(agent.weapon))

    @Action
    def Strike(agent):
        if not agent:
            raise RuntimeError("the fighter needs a sound weapon")
        return agent.weapon.Swing()

    @Rip
    def Disarm(agent):
        Contract.Delete(agent, "Armed")


charlie = Character("Charlie")
bob = Character("Bob")
Smith(charlie)
Smith(bob)
Fighter(charlie, weapon=charlie.Forge_Weapon("Charlie's sword"))
Fighter(bob, weapon=bob.Forge_Weapon("Bob's sword"))

assert charlie.weapon in Weapon[:]
assert charlie not in Weapon[:]
assert list(Weapon) == [charlie.weapon, bob.weapon]
assert charlie.Strike() == "Charlie's sword swings for 6"
```

The Action `Forge_Weapon` creates and trains the sword. The Record
`weapon` receives it. The Action `Strike` explicitly checks Charlie's
contract before using the sword. The sword's Action also checks its own
contract. Ordinary Actions have no automatic Post barrier.

Use `if agent:` for an Agent's contract truth. A false Agent needs its
promises repaired; it has not disappeared. `assert agent` is a concise
development guard, but Python removes assertions under `-O`. Use an
explicit `if` when the guard must remain in an optimized program.

## The curse belongs to the sword

```python
@Flag
class Cursed(Tag):

    @Action
    @Underlay
    def Swing(tool, underlay):
        return underlay() + ", and the curse bites"


Cursed(charlie.weapon)

assert charlie.weapon in Cursed[:]
assert charlie not in Cursed[:]
assert "Cursed" in charlie.weapon
assert not Keyword(charlie, "Cursed")
assert charlie.Strike() == "Charlie's sword swings for 6, and the curse bites"
assert charlie
```

Charlie holds a cursed sword; he has not gained `Cursed`. The sword's
Overlay changed, and Charlie's did not. Use `Keyword` when asking about
a Flag on an arbitrary Target: Python's ordinary `in` protocol may be
absent on an unflagged host.

## Presence, membership and soundness are different questions

`"weapon" @ charlie` asks whether the Contribution exists. It does not
read the value and does not say that the sword is present, Tagged or
sound. A Record containing `None` still exists.

```python
assert "weapon" @ charlie
assert charlie.weapon in Weapon[:]
assert charlie.weapon

charlie.weapon.damage = 0
assert charlie.weapon in Weapon[:]       # still a member
assert charlie.weapon in ~Weapon         # now deficient
assert not charlie.weapon
assert not charlie                        # Armed requires a sound sword
assert charlie in ~Fighter

try:
    charlie.Strike()
except RuntimeError:
    pass
else:
    raise AssertionError("the explicit guard must stop the strike")

charlie.weapon.damage = 6
assert charlie.weapon and charlie
```

The Tool's promises do not automatically become the bearer's promises.
`Armed` makes that dependency explicit. If Charlie only promises to hold
a Weapon, a broken Weapon may satisfy that weaker promise.

The Director's Agent truth ruling reserves an ordinary Agent's
`bool(agent)` for its visible Posts and refuses a host with an explicit
or inherited `__bool__` (STEP-SPEC-40). Use native truth for the verdict;
`Contract.Postconditions` raises the named failure when a Post fails.
Plain Python objects held in Records retain their own Python truth:
`bool(value)` alone does not establish that a value is an Agent. The
membership check in `Armed` establishes that before asking its truth.

`bool(Tag)` follows the same contract rule: its own visible Posts,
received from Pins, must hold. With no Posts it is true, even if its
Field is empty. Ask `len(Tag) > 0` for a sound member, `len(Tag[:])`
for the whole Field's size, and `len(~Tag)` for the defective count.
Conditions use ordinary names; a Post named `__bool__` is refused under
the condition naming
ruling in [#155](https://github.com/JulTob/Tag_Oriented_Programming/pull/155).
Write conditions with `return`, since an assertion alone is removed
under `-O`.

## Hand-over and the empty hand

Assignment hands over a reference, not the sword's Tags. Two bearers may
hold the same sword. `del` removes the held value.

```python
bob.weapon = charlie.weapon
del charlie.weapon

assert not ("weapon" @ charlie)
assert not charlie
assert bob.weapon in Cursed[:]

charlie.weapon = bob.weapon
assert charlie.weapon is bob.weapon
```

A plain Record admits any value. Its Post can judge an unsuitable value,
but it does not prevent the write:

```python
charlie.weapon = "a stick"
assert "weapon" @ charlie
assert not charlie

charlie.weapon = charlie.Forge_Weapon("Charlie's new sword")
assert charlie
```

`@Tool(Sword)` refuses a value outside the Python class `Sword` at the
write and keeps the previous value; it accepts an untagged Sword too.
`@Tool(Weapon)` refuses a value that is not a Weapon now, whatever its
class. `@Tool(Sword, Weapon)` asks both. Admission is separate from the
soundness requirement in `Armed`. See [Admission with `@Tool`](#admission-with-tool)
at the end of this page.

## Improvements belong in an Imprint

A Record may return the held value through its **stored seat**. An
Imprint changes it after the preceding Gainings are available.

```python
class Enchanter(Tag):

    @Record
    def weapon(agent, stored):
        return stored

    @Imprint
    def Sharpen(agent):
        agent.weapon.damage += 2


before = bob.weapon
Enchanter(bob)
assert bob.weapon is before
assert bob.weapon.damage == 8
```

This keeps the calculation and the act separate. When choosing whether
to reuse a value, test `stored is None`, not `stored or replacement`.
A deficient Agent is false but still exists.

An optional Record can start empty and be filled during training:

```python
class Squire(Smith):

    @Record
    def weapon(agent, stored):
        return stored

    @Post
    def Equipped(agent):
        return ("weapon" @ agent
                and agent.weapon is not None
                and agent.weapon in Weapon[:]
                and bool(agent.weapon))

    @Imprint
    def Equip(agent):
        if agent.weapon is None:
            agent.weapon = agent.Forge_Weapon(f"{agent.name}'s sword")


erin = Character("Erin")
Squire(erin)
assert erin.weapon in Weapon[:]
assert erin
```

Under the approved sequence
[STEP-SPEC-39 / #78](https://github.com/JulTob/Tag_Oriented_Programming/pull/78),
each Tag passes its Gate, gains Contributions in declaration order,
runs its Imprints, enters the Field, and is judged by Posts. A Gaining
failure before FieldAdding keeps its acquired Gains, including Posts,
without entering that Tag's Field. The Post remains available to judge
those Gains; do not exempt the Rogue from safety checks merely because it
is outside the Field. Tagging again starts a new attempt. An ordinary
Imprint failure instead gives a named Training Warning, lets later
Imprints run, and admits the Agent. Its Posts decide soundness; Rip is
required before a new training attempt for that Tag.

A Record that requires a trained Agent receives that Agent already
prepared. An optional Record may start at `None` before its Imprint
equips the bearer. Both patterns keep performative work out of Record
builders.

## A bonded tool

`@Constant` protects the binding. Prepare the sword first; then receive
it in the Constant Record. Constant does not freeze the sword's contents
or its Tags.

```python
class Oathbound(Tag):

    @Constant
    @Record
    def relic(agent, *, relic):
        return relic


relic = bob.Forge_Weapon("the relic")
Oathbound(bob, relic=relic)
try:
    bob.relic = Sword("a copy")
except TagCompositionError:
    pass
else:
    raise AssertionError("a bonded tool cannot be replaced")

Cursed(bob.relic)
assert bob.relic is relic and bob.relic in Cursed[:]
```

An established Constant binding also survives Rip. Reapplication keeps
it without rerunning its builder. If the sword has become deficient or
Rogue, a Post must judge that current state; Constant does not repair it.

## Each Agent has its own door

Holding an Agent does not grant access to its Secrets. Use the Actions
it makes available.

```python
class Vault(Tag):

    @Secret
    @Record
    def combination(tool):
        return "1234"

    @Action
    def Open(tool):
        return tool.combination


class Guard(Tag):

    @Record
    def vault(agent, *, vault):
        return vault

    @Action
    def Crack(agent):
        return agent.vault.combination


vault = Sword("the vault")
Vault(vault)
ann = Character("Ann")
Guard(ann, vault=vault)
assert ann.vault.Open() == "1234"
try:
    ann.Crack()
except AttributeError:
    pass
else:
    raise AssertionError("holding the vault does not open its door")
```

An Agent's door stays open while its own Action or protocol runs. If a
bearer Action passes the bearer to a Tool's Action, that nested call
runs while the bearer's door is still open and can read its Secrets
through that reference. The same call made from outside the bearer's
functions cannot. Tools use the existing doors; they do not introduce
isolation between nested calls.

`@Secret` on `weapon` hides the bearer's Record. It does not hide the
sword from someone who already holds another reference to it.

## Rip does not cascade

```python
del Fighter[charlie]

assert charlie not in Fighter[:]
assert isinstance(charlie, Fighter)
assert "weapon" @ charlie
assert charlie          # Disarm explicitly ended Armed

del Weapon[bob.weapon]
assert bob.weapon not in Weapon[:]
assert isinstance(bob.weapon, Weapon)
assert not bob          # his Armed Post still requires membership

Weapon(bob.weapon)
assert bob
```

The bearer keeps the Record after Rip unless a Rip protocol removes it.
The sword keeps its own acquired Contributions after its Rip. It can
therefore become a held Rogue. Admission happened earlier; current
membership and soundness remain questions for Posts.

A Record holds its value strongly. A Field holds an Agent weakly.
Deleting the bearer does not Rip the Tool: the sword lives wherever
another reference still holds it.

## Failed training belongs to the Agent being trained

A Tool's Gate refusal happens at the Tool's Tagging statement. It has
not become a failure of a Record builder:

```python
class Holy(Tag):

    @Pre
    def Blessed_Steel(tool):
        return tool.name != "a stick"


stick = Sword("a stick")
try:
    Holy(stick)
except Precondition.Blessed_Steel:
    pass
else:
    raise AssertionError("the Tool's Gate must refuse the stick")
assert stick not in Holy[:]
```

When an Imprint performs another Tagging and that Tagging raises, the
Imprint gives a named Training Warning with the underlying failure's type,
text and source location. Later Imprints still run. The Tool and bearer
have separate histories: a later bearer failure does not undo completed
Tool Taggings. A Gaining failure before Field entry keeps actual Gains on
a Rogue; an ordinary Imprint failure admits its Agent for Post judgment.
The program chooses how to repair or retire them. Rip is another act with
its own protocol; it is not restoration to a snapshot and can itself fail.

## A shared tool

An ordinary Report initializes for each receiving Tag. A Constant
Report keeps the declaring Tag's exact value for all its Shapes. Prepare
and train that Agent before the Report reads it.

```python
engine = bob.Forge_Weapon("the siege engine")


class Guild(Tag):

    @Constant
    @Report
    def engine(tag):
        return engine


class Royal_Guild(Guild):
    pass


assert Guild.engine is engine
assert Royal_Guild.engine is Guild.engine
assert Guild.engine in Weapon[:]
```

This uses existing Report rules. The initial `@Tool` proposal concerns
Agent Records; it does not add kind admission to Reports or Pins.

## Admission with `@Tool`

`@Tool` marks an ordinary Record whose value is checked against a
**kind** at the Gain and at every later write. A kind is a Python class
(`Sword`: an instance), a specific Tag (`Weapon`: a member, now), or
both. Admission never Tags the received value. `@Record` may also be
written, but is redundant.

With a class, admission accepts a Sword whether it is untagged, a member
of Weapon, deficient or Rogue:

```python
class Armed_With(Tag):

    @Tool(Sword)                        # the kind is a Python class
    def weapon(agent, *, weapon):
        return weapon


sword = bob.Forge_Weapon("the prepared sword")
Armed_With(ann, weapon=sword)
try:
    ann.weapon = "a stick"
except TagCompositionError:
    pass
assert ann.weapon is sword

try:
    ann.weapon = None
except TagCompositionError:
    pass
assert ann.weapon is sword

untrained = Sword("the untrained sword")
ann.weapon = untrained                  # admitted by Class, no automatic Tagging
assert ann.weapon is untrained
assert untrained not in Weapon[:]

del ann.weapon
assert not ("weapon" @ ann)


class Empty_Hand(Tag):

    @Tool(Sword | None)                 # the empty hand, declared where readers see it
    def weapon(agent):
        return None


finn = Character("Finn")
Empty_Hand(finn)
assert "weapon" @ finn
assert finn.weapon is None
```

`@Tool(Sword | None)` admits a Sword or an empty value. `del` removes
the value altogether. Neither class compatibility nor an empty value is
equivalent to a sound member of the `Weapon` Tag. Posts establish any
contract requirements. An untagged value still has ordinary Python
truth; `if tool:` means Post validity only once the value is an Agent
under TOP's Agent truth rules.

With a Tag, admission asks membership **now**, `in Weapon[:]`, sound or
deficient, and never a Tag's `isinstance` history. A plain Sword is
refused; a sword that leaves `Weapon` stays in hand, a Rogue, and is
refused only if seated again:

```python
class Knight(Tag):

    @Tool(Weapon)                       # the kind is a Tag
    def weapon(agent, *, weapon):
        return weapon


dana = Character("Dana")
Knight(dana, weapon=bob.Forge_Weapon("Dana's sword"))
try:
    dana.weapon = Sword("an untrained sword")   # refused: not a Weapon now
except TagCompositionError:
    pass
assert dana.weapon in Weapon[:]

rogue = dana.weapon
del Weapon[rogue]
assert dana.weapon is rogue             # admission is a gate, asked at the write
try:
    finn.weapon = rogue                 # a class kind: still a Sword, admitted
except TagCompositionError:
    raise AssertionError("a Sword is a Sword")
Weapon(rogue)                           # a fresh tagging repairs it
```

Both at once, `@Tool(Sword, Weapon)`, admits only a Sword that is a
Weapon now:

```python
class Staff:
    def __init__(staff, name):
        staff.name = name


class Templar(Tag):

    @Tool(Sword, Weapon)                # both: a Sword that is a Weapon
    def weapon(agent, *, weapon):
        return weapon


gwen = Character("Gwen")
Templar(gwen, weapon=bob.Forge_Weapon("Gwen's sword"))

staff = Staff("a staff")
Weapon(staff)                           # a Weapon, but not a Sword
try:
    gwen.weapon = staff
except TagCompositionError:
    pass

try:
    gwen.weapon = Sword("a plain sword")  # a Sword, but not a Weapon
except TagCompositionError:
    pass
assert gwen.weapon in Weapon[:] and isinstance(gwen.weapon, Sword)
```

Native class unions keep Python's meaning: `@Tool(Sword | Staff)` admits
either class, `@Tool(Weapon | Staff)` a Weapon or a Staff. `Weapon | Blessed`
is the Field algebra ("sound in either"), not a kind: write
`@Tool(Weapon, Blessed)` for both, and a common Base Tag for either. The
root `Tag` and `object` name no kind; a Pin does not either. If a Tool
is declared with `@Tool(type)` and holds a Tag itself, `bool(Tag)` checks
that Tag's own visible Posts, just as it does for another Agent. It does
not check the held Tag's population; `len(Tag) > 0` asks whether that
population has a sound member.

The earlier `Squire` recipe can replace its `@Record` mark with
`@Tool(Weapon | None)`: the builder returns the stored sword or `None`,
and `Equip` performs the forging and assignment. `Equipped` requires
soundness after training. Admission and that Post requirement remain
separate.

The guard follows the effective Tool Record: it survives Rip
and deletion of the value, and ends when `@Delete` removes the
Contribution or an allowed plain Record or Action replaces it. Constant
protects against those replacements. A bearer may explicitly hold itself;
an author who requires a distinct value can express that requirement in
a Post, such as `return agent.weapon is not agent`.

The held object keeps its Python protocols; if tagged, normal Agent rules
apply. A Tool Record under a protocol name does not turn its value into
the bearer's Python protocol. Ordinary assignment still checks its Class.
Direct kernel writes to protocol-named Records, like raw dictionary
writes, can bypass admission. Tools provide no Python sandbox.

Tools do not imply exclusive ownership, reverse references or Links.
A Tool is one held value. The separate
[Links proposal](https://github.com/JulTob/Tag_Oriented_Programming/pull/26)
is design history for relations between Agents, not a current API to
use in place of a Tool.

## Questions to keep separate

| Question | Expression |
| --- | --- |
| Does the Contribution exist? | `"weapon" @ charlie` |
| Is the optional value empty? | `charlie.weapon is None`, after checking presence |
| Is it a Weapon now, including a deficient one? | `charlie.weapon in Weapon[:]` |
| Do this Agent Tool's own Posts hold? | `bool(charlie.weapon)` |
| Is it a deficient member? | `charlie.weapon in ~Weapon` |
| Do the bearer's Posts hold? | `if charlie:` |
| Who holds this particular sword? | `[f for f in Fighter[:] if "weapon" @ f and f.weapon is sword]` |
