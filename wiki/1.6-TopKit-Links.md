# Links: one Agent's Tag of Contacts

A Tool answers which object an Agent holds in a checked Record. A Link
answers which Contacts belong to one of that Agent's Fields, with Gains
about each relationship. For equipment, a weapon's damage belongs to the
weapon; where Ari carries that weapon belongs to their Pair.

The declaration is a blueprint. `ari.Carries` is the actual Tag, and
`ari.Carries(sword)` applies it to the sword as its Contact. Bob's
`bob.Carries` is a different Tag with a different Field. Linking the same
sword to both creates two independent Pairs; it does not imply ownership,
exclusivity, or a reciprocal Link.

The Python blocks below run in order as one program. The complete
[GenLegend equipment example](https://github.com/JulTob/Tag_Oriented_Programming/blob/main/examples/equipment_links.py) combines this
pattern with a checked Tool and an explicit attack guard.

## Declare the relationship

```python
from TopKit import (Action, Imprint, Link, Post, Pre, Record, Report, Rip,
                    Tag, TagCompositionError, TagResolutionError,
                    agent, contact)


class Character:
    def __init__(self, name):
        self.name = name


class Item:
    def __init__(self, name):
        self.name = name


class Inventory(Tag):
    @Link(agent, contact)
    class Carries(Tag):
        @Pre
        def Is_Equipment(agent, contact):
            return isinstance(contact, Item)

        @Record
        def position(agent, contact, *, position="pack"):
            return position

        @Post
        def Stored(agent, contact):
            return agent.Carries[contact].position in ("hand", "pack", "belt")

        @Action
        def Move(agent, contact, position):
            agent.Carries[contact].position = position

        @Report
        def capacity(link):
            return 20


ari, bob = Character("Ari"), Character("Bob")
sword, lantern = Item("sword"), Item("lantern")
Inventory(ari)
Inventory(bob)
ari.Carries(sword, position="hand")
ari.Carries(lantern)
bob.Carries(sword)
```

The first two positional parameters of a Pair protocol are its actual
Agent and Contact. Their names are the programmer's choice. Pair Records
and Actions belong to the relationship; the Contact does not acquire
`position` merely by entering Carries. A `@Public` Pair Record or Action
explicitly publishes access onto the Contact, guarded by its current
membership and the Pair's Posts.

```python
assert ari.Carries is not bob.Carries
assert ari.Carries[sword].position == "hand"
assert bob.Carries[sword].position == "pack"
assert not ("position" @ sword)
assert "position" @ ari.Carries[sword]
```

Reports and Operations belong to the actual Link Tag. This Report is
shared by Ari's Carries Pairs, while Bob's Carries keeps its own value.

```python
ari.Carries.capacity = 2
assert ari.Carries[sword].capacity == 2
assert ari.Carries[lantern].capacity == 2
assert bob.Carries.capacity == 20
```

## Inspect and repair a Pair

Membership follows the ordinary population spellings. Sound Link
membership requires the Contact's Posts and that Link's Pair Posts to hold.
A raw Pair view remains available to inspect an admitted, broken Pair.

| Expression | Question |
| --- | --- |
| `sword in ari.Carries` | Is this a free, valid Contact with a valid Pair here? |
| `sword in ~ari.Carries` | Is this an admitted, free Contact whose Contact or Pair Posts fail? |
| `sword in ari.Carries[:]` | Is the Contact admitted, regardless of validity or custody? |
| `sword in ari.Carries[...]` | Does this Link owe saved cleanup for the Contact? |

```python
view = ari.Carries[sword]
move = view.Move
move("floor")
assert sword in ari.Carries[:]
assert sword in ~ari.Carries
assert sword not in ari.Carries
assert view.position == "floor"
move("belt")
assert sword in ari.Carries
assert bob.Carries[sword].position == "pack"
```

An ordinary Action still needs explicit guards for the conditions it
requires. A character's equipment Post may require the selected Tool to
belong to `character.Carries`; the [equipment example](https://github.com/JulTob/Tag_Oriented_Programming/blob/main/examples/equipment_links.py)
shows that rule and guards its Attack Action. A Tool alone does not impose
that carrying requirement.

## Rip and reLink

`del ari.Carries[sword]` ends this relationship. It leaves Bob's carrying
relationship, the weapon's own Tags, and unrelated Tool selections intact.
Calling an already-active Link is a no-op; Rip before reLink when fresh
training is intended.

A saved Pair view is a soft call to the Link and Contact. It resolves the
current Pair every time, including when a saved Action is invoked. It
refuses access between Rip and reLink, then follows the fresh Pair.

```python
del ari.Carries[sword]
assert sword not in ari.Carries[:]
assert sword in bob.Carries
assert lantern in ari.Carries
try:
    view.position
except TagResolutionError:
    pass
else:
    raise AssertionError("the Contact is no longer admitted here")

ari.Carries(sword, position="pack")
assert view.position == "pack"
move("hand")
assert view.position == "hand"
```

`del ari.Carries[:]` revokes all starting Contacts before its first Rip
protocol runs. Cleanup then stops at its first failure or interruption.
Unfinished work stays in the Link's Safehouse, separate from its sound and
broken populations. Use `del ari.Carries[contact]` to retry that Contact's
saved work; successful earlier protocols do not run again. An ordinary
act on an arrested Contact also retries saved cleanup and refuses the act
if it still fails. The [Tagging guide](https://github.com/JulTob/Tag_Oriented_Programming/blob/main/wiki/1.5-TopKit-Tagging.md) explains this
ordinary Rip behavior with a complete retry example.

## Ordered Form entries target the Contact

Every entry in a Link's header is an earlier Tagging of the current
Contact, in the written order. Each deferred `agent` or `contact`
selection is resolved when its turn arrives, after earlier turns finish.
There is no shared Field or implicit reciprocal Link.

```python
turns = []


class Network(Tag):
    @Imprint
    def Register(target):
        turns.append(("Network", target.name))


class Connections(Tag):
    @Link(agent, contact)
    class Knows(Tag):
        @Imprint
        def Meet(agent, contact):
            turns.append(("Knows", agent.name, contact.name))

    @Link(agent, contact)
    class Registre(Tag):
        @Imprint
        def Register(agent, contact):
            turns.append(("Registre", agent.name, contact.name))


ruth, server = Character("Ruth"), Character("Server")
Connections(ari)
Connections(ruth)
Connections(server)


class Trusting(Tag):
    @Link(agent, contact)
    class Trusts(Network, agent.Knows, contact.Knows, server.Registre):
        @Imprint
        def Reciprocal(agent, contact):
            contact.Knows(agent)


Trusting(ari)
ari.Trusts(ruth)
assert turns == [
    ("Network", "Ruth"),
    ("Knows", "Ari", "Ruth"),
    ("Knows", "Ruth", "Ruth"),
    ("Registre", "Server", "Ruth"),
    ("Knows", "Ruth", "Ari"),
]
```

For `ari.Trusts(ruth)`, `contact.Knows` really means `ruth.Knows(ruth)`.
The reciprocal `ruth.Knows(ari)` happens only because the Imprint explicitly
calls it. Each actual Link keeps its own Field and Pair.

## Python profile

Link training follows ordinary Tagging. Target preparation or Gate refusal
leaves no Contact membership. After preparation succeeds, each ordinary
Record-initializer or Imprint failure emits its named training warning,
later training continues, and the Contact enters the Field before Posts
judge it. Passing Posts return the valid result with warnings; failed Posts
produce the final Post error and leave a broken member. A Python
interruption stops later training and is preserved after admission and Post
checking. A fresh Link Tagging requires a valid Contact; repair through
existing Actions or Records first. Calling an active Link remains a no-op,
not a repair protocol: Rip before a new training attempt. No Fix API is
implied by these examples.

The imported `agent` and `contact` also work inside zero-parameter Link
protocols as contextual references. They forward named access and are
recognized at TOP Target and membership boundaries, but Python `is` and
`type` still see proxy objects. Declare the two protocol parameters, as
above, when actual object identity or general Python APIs need the objects.

Lazy Action and Operation results resume inside the Link's contextual
seats and custody checks. They iterate or await, including use with
`asyncio.create_task`, but are protocol proxies: native `inspect` checks
such as `inspect.isgenerator` and `inspect.iscoroutine` return False.
Preconditions, Posts, Imprints and Rip protocols remain synchronous.
Use sequential cleanup; shared-task mutation and arbitrary captured Host
methods are outside this release's custody guarantee.

An ordinary-only class header still passes Python's class-creation rules
before `@Link` captures it. Contextual header entries use TOP's ordered
Form capture. The finished blueprint exposes only its own declarations;
an actual Link cannot be reclassified as a Pin.
