# Pins: organizing Tags

An ordinary Tag categorizes object Targets and acts as their Agency. A
named Pin organizes Tags and Pins. Applying an existing Pin to a Tag is
normal Pinning: the Target keeps its category, identity and own Field.
That Field may be empty or populated.

Every Python block below runs in order with the `Pin` declaration Base.
Declare a concrete Pin with `class Rare(Pin)`, then apply that named Pin
to eligible Targets. Ordinary Tags cannot convert into Pins.

## Categorize the equipment

```python
from TopKit import Pin, Record, Tag, TagCompositionError


class Item:
    pass


class Weapon(Tag):
    @Record
    def damage(item):
        return 6


sword = Item()
Weapon(sword)
assert sword in Weapon[:]
assert sword.damage == 6
```

The sword is an object Target. `Weapon` is the Tag that categorizes it.
A sword held by another Agent's `@Tool` Record is still an object; the
Tool modifier does not turn the sword into a Tag or Pin.

## Organize the category

```python
class Rare(Pin):
    @Record
    def rarity(tag):
        return "rare"


original_weapon = Weapon
Rare(Weapon)                         # Weapon already has a sword in its Field
assert Weapon is original_weapon
assert Weapon in Rare[:]
assert sword in Weapon[:]
assert sword not in Rare[:]
assert Weapon.rarity == "rare"       # the Pin's receiver is Weapon
assert not ("rarity" @ sword)         # no Public publication to its Agents
```

`Rare(Weapon)` does not make Weapon a Pin and does not Tag the sword as
Rare. Ordinary Pin Preconditions, Posts and contribution rules still
apply; an occupied Target Field is not itself a category error.

## A Pin can itself be organized

```python
class Reviewed(Pin):
    pass


Reviewed(Rare)
assert Rare in Reviewed[:]
assert Weapon not in Reviewed[:]
assert Weapon in Rare[:]

del Rare[Weapon]
assert Weapon not in Rare[:]
assert sword in Weapon[:]
assert Rare in Reviewed[:]
```

Each Field is independent. Ripping Weapon from Rare does not Rip the
sword from Weapon or Rare from Reviewed. Rip follows ordinary Gain and
Post lifetimes; ending membership does not automatically undo every Gain.

## Keep the receiver distinction

```python
try:
    Weapon(Reviewed)                 # ordinary Tags do not target Tags
except TypeError:
    pass
else:
    raise AssertionError("an ordinary Tag accepted a Tag Target")

try:
    Rare(sword)                      # Pins do not target ordinary objects
except TagCompositionError:
    pass
else:
    raise AssertionError("a Pin accepted an object Target")
```

Actual Link Tags, such as `ari.Carries`, are also Tag-kind receivers in
the agreed design. Links are not implemented on this guide's main base;
a Link blueprint is not the actual Link Tag. No Link API is assumed here.

## Declare, then apply

`class Rare(Pin)` declares a Pin; `Rare(T)` applies that existing named
Pin. The declaration root cannot be called as `Pin(existing_tag)` to
convert an ordinary Tag, including an unused or Ripped Tag. The root has
no own Field or concrete application. This replaces the former
`@Pin class Rare(Tag)` marking API rather than adding another conversion
route. Ordinary Tags and Pins retain their declared receiver categories.
