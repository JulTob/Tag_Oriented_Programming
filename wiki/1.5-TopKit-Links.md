# Links: a Tag of one's own

A Tag says one thing about one Agent: *Ruth is a Wizard*. Many programs
also need to say one thing about two: *Charlie knows Ruth*, *this drone
follows that one*. A **Link** says it.

The idea is small. Fix the first place of *Charlie knows Ruth*, and what
is left, *known by Charlie*, is an ordinary one-place Tag. So each Agent
gets **a Tag of its own**: `charlie.Knows`. Its Field holds the people
Charlie knows. Bob's Link is another Tag with another Field.

> **Status.** This page documents the Links implementation under review.
> Its `python` blocks form one program. The design is recorded in
> [STEP-SPEC-22](https://github.com/JulTob/Tag_Oriented_Programming/blob/main/steps/spec/STEP-SPEC-22-links.md)
> (Vetting) and §1.10 of the
> [Specification](https://github.com/JulTob/Tag_Oriented_Programming/blob/main/spec/SPECIFICATION.md).

## Five words

| Word | Meaning | In the example |
| --- | --- | --- |
| **Relation** | The class marked `@Link` inside a Tag's body: a template, never a Tag in play. | `Social.Knows` |
| **Link** | The Tag one Agent holds under the Relation's name. | `charlie.Knows` |
| **The Link's Agent** | The one who holds the Link and acts through it. | Charlie |
| **Contact** | A member of a Link's Field: whom the Agent is related to. | Ruth |
| **Pair** | One Agent and one Contact, linked. What is *between* them lives here. | `charlie.Knows[ruth]` |

## Declare a Relation, then link a Contact

```python
import gc

from TopKit import (Action, Contract, Imprint, Link, Post, Pre, Public,
                    Record, Report, Rip, Secret, Tag, TagCompositionError,
                    TagPreconditionError, TagRogueAccessError, Tags,
                    Underlay)


class Person:
    def __init__(person, name):
        person.name = name
        person.honest = True

    def __repr__(person):
        return person.name


class Social(Tag):

    @Link
    class Knows(Tag):

        @Pre
        def Not_Oneself(agent, contact):
            return contact is not agent

        @Record
        def since(agent, contact, *, since=None):
            return since

        def Greet(agent, contact):
            return f"{agent.name} waves at {contact.name}"


charlie = Person("Charlie")
bob = Person("Bob")
ruth = Person("Ruth")

Social(charlie)
Social(bob)
charlie.Knows(ruth, since=2010)

assert ruth in charlie.Knows
assert ruth not in bob.Knows
assert charlie.Knows is not bob.Knows
assert list(charlie.Knows) == [ruth]
```

Read it in three steps:

1. `Social` is an ordinary Tag. Inside its body, `@Link` marks the class
   `Knows` as a **Relation**: a template.
2. When Charlie gains `Social`, he gains a **Link** built from that
   template: `charlie.Knows`. It is a real Tag, made for Charlie alone.
   Bob gains another one.
3. `charlie.Knows(ruth, since=2010)` tags Ruth with Charlie's Link. She
   is now a **Contact** of Charlie's. Bob's Link knows nothing of her.

So a Link is the whole of `charlie.Knows`, never `Knows`. The name is
only where each Agent keeps its own: `ruth in bob.Knows` is a question
Bob's Link answers, and `ruth in Social.Knows` is no question at all.

Every function in a Relation has **two seats**: first the Link's Agent,
then the Contact. After the two seats, each kind reads what it always
reads: a Record its inputs by name, an Action its arguments. The
Precondition `Not_Oneself` reads both seats and refuses a self-link.

## The Pair holds what is between them

`since` is not a fact about Ruth, and not a fact about Charlie. It is a
fact about *the two of them*. So it lives on the **Pair**,
`charlie.Knows[ruth]`, and nothing lands on Ruth but her membership.

```python
pair = charlie.Knows[ruth]

assert pair.since == 2010
assert pair.Greet() == "Charlie waves at Ruth"

pair.since = 2011
assert charlie.Knows[ruth].since == 2011

assert not ("since" @ ruth)
assert not ("Greet" @ ruth)
```

The Pair is reached only through the Link, and it is live: a write on
it is seen the next time anyone reads it.

## The Gate decides before training

Linking is a tagging of the Contact, so it has a gate, the Relation's
Preconditions. A refused linking leaves everything as it was.

```python
try:
    charlie.Knows(charlie)
except TagPreconditionError:
    pass
else:
    raise AssertionError("Not_Oneself must refuse a self-link")

assert charlie not in charlie.Knows
assert list(charlie.Knows) == [ruth]
```

## The slot is closed and read-only

A Link sits in the Agent's namespace under the Relation's name, the way
a Record does. Unlike a Record, its slot is **closed**: nothing else may
arrive at that name, and the program cannot assign or delete it.

```python
try:
    charlie.Knows = "someone else"
except TagCompositionError:
    pass
else:
    raise AssertionError("a Link is read-only")

try:
    del charlie.Knows
except TagCompositionError:
    pass
else:
    raise AssertionError("a Link cannot be deleted by name")

assert ruth in charlie.Knows
```

Links are **sticky**, like every contribution: Rip of `Social` leaves
`charlie.Knows` with Charlie, and applying `Social` again keeps the same
Link, its Field and its Pairs.

```python
held = charlie.Knows

del Social[charlie]
assert charlie.Knows is held and ruth in charlie.Knows

Social(charlie)
assert charlie.Knows is held
```

## Trust builds on knowing

A Relation may have a Base: another Relation of the same Tag. Trusting
someone then links them as known first. A Link and its Base Links share
**one Pair** for each Contact.

```python
class Circle(Tag):

    @Link
    class Knows(Tag):

        @Record
        def since(agent, contact, *, since=None):
            return since

    @Link
    class Trusts(Knows):

        @Post
        def Still_Honest(agent, contact):
            return contact.honest

        def Confide(agent, contact, secret):
            return f"{agent.name} tells {contact.name}: {secret}"


hal = Person("Hal")
Circle(hal)
hal.Trusts(ruth, since=2015)

assert ruth in hal.Knows
assert hal.Knows[ruth] is hal.Trusts[ruth]
assert hal.Knows[ruth].since == 2015
assert hal.Trusts[ruth].Confide("the map") == "Hal tells Ruth: the map"
```

Hal is a new Agent here on purpose. Bob already holds `Social.Knows`
under the name `Knows`, and a Link's slot is closed. So `Circle(bob)` is
refused, and nothing changes: two unrelated meanings of `bob.Knows`
would be a trap.

```python
try:
    Circle(bob)
except TagCompositionError:
    pass
else:
    raise AssertionError("bob.Knows is already Social's")

assert bob not in Circle[:]
assert not ("Trusts" @ bob)
assert bob.Knows is not hal.Knows
```

The Post `Still_Honest` is a promise about the **Pair**, not about Ruth.
When it breaks, the Pair is defective. Ruth is not.

```python
ruth.honest = False

assert not hal.Trusts[ruth]
assert hal.Trusts[ruth].Still_Honest is False
assert ruth in ~hal.Trusts
assert bool(ruth)

ruth.honest = True
assert hal.Trusts[ruth]
```

The Bases resolve **per Agent**: `hal.Trusts` is a Shape of `hal.Knows`,
never of Charlie's.

Unlinking a Base Link ends only that membership. Ruth stays in `Trusts`,
and its shared Pair keeps what `Knows` gave it unless a Rip deliberately
changes those Gains. If `Trusts` needs `Knows` to remain active, say so
with a Post on the Pair.

```python
pair = hal.Trusts[ruth]
del hal.Knows[ruth]
assert ruth not in hal.Knows[:]
assert ruth in hal.Trusts[:]
assert hal.Trusts[ruth] is pair
assert pair.since == 2015

hal.Trusts(ruth)                  # already a Contact: does not reapply Knows
assert ruth not in hal.Knows[:]

hal.Knows(ruth, since=2015)      # explicitly train Knows again
assert ruth in hal.Knows[:]

del hal.Trusts[ruth]
del hal.Knows[ruth]
assert ruth not in hal.Knows
```

## A spy rewrites what knowing means

A Shape of the declaring Tag may **extend** its Base's Relation by name.
When Charlie becomes a Spy, the Link he already holds gains the new
Layer. It keeps its identity, its Field and its history, and every Pair
it holds is extended in the same call, one Pair at a time. Each follows
ordinary Tagging: Gate, ordered Gainings, Imprints, Field entry, then Posts.
If Ruth completes and Bob's later Record fails, Ruth keeps her training
and Bob keeps his partial Gains. The unfinished declaring Shape is absent;
its acquired Link Layer stays. Retrying the Shape completes the missing
Pair training without repeating completed turns.

```python
class Spy(Social):

    @Link
    class Knows(Social.Knows):

        @Secret
        @Record
        def cover_story(agent, contact):
            return "a cousin from Lyon"

        @Action
        @Underlay
        def Greet(agent, contact, underlay):
            return underlay() + f", as {agent.Knows[contact].cover_story}"


before = charlie.Knows
Spy(charlie)

assert charlie.Knows is before
assert charlie.Knows[ruth].Greet() == "Charlie waves at Ruth, as a cousin from Lyon"

try:
    charlie.Knows[ruth].cover_story
except AttributeError:
    pass
else:
    raise AssertionError("a secret stays inside the Link's own functions")
```

`cover_story` is `@Secret`: it resolves only while the Link's own
functions run. `Greet` reads it; the program outside cannot.

A same-name Relation that does not name its Base is refused when the
class is made: two different meanings of `Knows` on one Agent would be
a trap.

The Link itself is granted in declaration order alongside Actions, Records
and conditions. A later Record builder can read a Link declared above it.
A failure after that Gaining keeps the Link on the Agent, even if the
declaring Tag never reaches its Field.

Linking through a Shape applies each Base first. A Gate refusal stops the
current turn; a failed Gaining or Imprint keeps that Pair's actual Gains
and Posts but leaves the Contact outside the unfinished Link. Earlier
completed Base linkings stay. Another linking starts fresh training for
the unfinished turn. Posts run after admission, so a broken Post leaves
a defective member. An extension cannot apply a Shape over a Base whose
training is still underway.

## A bounded Link

A Report of a Relation takes the Link alone, one seat, and belongs to
the Link: `agent.Knows.capacity`. A gate may read it.

```python
class Small_Talk(Tag):

    @Link
    class Chats(Tag):

        @Report
        def capacity(link):
            return 2

        @Pre
        def Has_Room(agent, contact):
            return len(agent.Chats[:]) < agent.Chats.capacity


Small_Talk(bob)
bob.Chats(charlie)
bob.Chats(ruth)

try:
    bob.Chats(Person("Dora"))
except TagPreconditionError:
    pass
else:
    raise AssertionError("Has_Room must refuse a third")

assert bob.Chats.capacity == 2
assert len(bob.Chats[:]) == 2
```

## Seen by the Contact: lines, and the doors

By default a Contact sees nothing of the Link but her membership. A
`@Public` member of the Relation is a **line** onto her: she may call it,
and it runs as the Pair's member, with the Agent in the first seat.

```python
class Club(Tag):

    @Secret
    @Record
    def motto(agent):
        return "never on Mondays"

    @Link
    class Member(Tag):

        @Public
        def Welcome(agent, contact):
            return f"{agent.name} welcomes {contact.name}"

        @Public
        @Record
        def badge(agent, contact, *, badge=None):
            return badge

        def Whisper(agent, contact):
            return agent.motto


Club(charlie)
charlie.Member(ruth, badge=7)

assert ruth.Welcome() == "Charlie welcomes Ruth"
assert ruth.badge == 7

charlie.Member[ruth].badge = 9
assert ruth.badge == 9

assert charlie.Member[ruth].Whisper() == "never on Mondays"
assert not ("Whisper" @ ruth)
```

Three things to see here:

- **A line reads live, and is read-only on her.** `ruth.badge` follows
  the Pair, and `ruth.badge = 1` is refused.
- **The doors.** A Link's functions run inside the composition door of
  the Link's Agent and of the Pair, never the door of the Contact they
  are about. `Whisper` reads Charlie's secret `motto`. The Link's code
  about Ruth never reads Ruth's secrets, even when Ruth herself calls the
  line. The doors hold while the Link's code runs, and a generator or a
  coroutine function of the Relation takes each step behind them, so a
  Pair Action may `yield` or `await`. An async generator is refused: the
  event loop closes it by itself, outside them.
- **A `@Secret` member stays in-house**, and an unmarked member is
  reached only through the Pair. Nothing unpublished of the Link reaches
  Ruth, not even through her own Tag views.

A line answers members only. Once Ruth is unlinked, calling it raises a
Rogue Access Failure: the line is sticky, its answer is not.

```python
del charlie.Member[ruth]

try:
    ruth.Welcome()
except TagRogueAccessError:
    pass
else:
    raise AssertionError("an unlinked Contact's line answers no more")
```

## One direction

A Link points **from** its Agent **to** its Contacts. Nothing public on
Ruth names the Agents who link her, and nothing public on a Link or a
Pair names its Agent.

```python
assert "Knows" not in [tag.__name__ for tag in Tags(ruth)]
assert not ("Knows" @ ruth)

assert isinstance(ruth, charlie.Knows)
assert "Charlie" not in repr(charlie.Knows)
```

Asked with the Link in hand, `isinstance(ruth, charlie.Knows)` answers.
Because a Link never names its Agent, two Agents' Links print alike;
tell them apart by holding them through their Agent, `charlie.Knows`,
or by comparing with `is`.
To find who knows Ruth, walk the Agents you have:
`[a for a in Social[:] if ruth in a.Knows]`. A Link that should answer
back says so in its own Imprint, as the next section shows.

## Two ways, written down

A Link is one-way. Two-way knowing is two Links, and an Imprint writes
the second one in plain sight, before the first Contact enters its Field.
Repeating a completed linking or the same linking already in training is
a no-op, so the echo stops after one round.

```python
class Friendly(Tag):

    @Link
    class Friends(Tag):

        @Imprint
        def Both_Ways(agent, contact):
            Friendly(contact)
            contact.Friends(agent)


ann = Person("Ann")
cal = Person("Cal")
Friendly(ann)
ann.Friends(cal)

assert cal in ann.Friends
assert ann in cal.Friends
```

## Peers: when neither holds the other

Two Agents at the same level are not a Link. When the program needs one
pair of peers, they are members of one ordinary Tag whose gate keeps its
Field at two. When it needs many pairs, the pair itself becomes an Agent,
and its Link holds the two peers as Contacts:

```python
class Wedding:
    pass


class Bond(Tag):

    @Link
    class Partners(Tag):

        @Pre
        def Two_Sides(agent, contact):
            return len(agent.Partners[:]) < 2


wedding = Wedding()
Bond(wedding)
wedding.Partners(ann)
wedding.Partners(cal)

try:
    wedding.Partners(Person("Eve"))
except TagPreconditionError:
    pass
else:
    raise AssertionError("a wedding has two sides")

assert set(wedding.Partners) == {ann, cal}
```

## Ending

`del charlie.Knows[ruth]` ends her membership, and the Relation's `@Rip`
teardowns run with both seats. A Contact's deletion unlinks her. The
Agent's deletion ends its Links, after its own teardowns.

```python
farewells = []


class Network(Tag):

    @Link
    class Follows(Tag):

        @Rip
        def Unfollow(agent, contact):
            farewells.append((agent.name, contact.name))


dora = Person("Dora")
fay = Person("Fay")
gus = Person("Gus")
Network(dora)
dora.Follows(fay)
dora.Follows(gus)

del dora.Follows[fay]
assert farewells == [("Dora", "Fay")]

del gus
gc.collect()
assert farewells == [("Dora", "Fay"), ("Dora", "Gus")]
assert list(dora.Follows) == []
```

`del dora.Follows[:]` removes every starting Contact from that Link's
Field and places them in its Safehouse before the first Pair teardown.
It then runs the saved teardowns one Contact at a time. If one fails,
that Contact and the later pending Contacts stay in the Safehouse;
`del dora.Follows[fay]` explicitly retries Fay's unfinished Rip. A Link
never keeps its Agent alive: the kit holds the Agent weakly. A Contact
with unfinished cleanup is held by the Safehouse until it succeeds.

## The Relation itself

A Relation is a template with no Field. `Knows` by itself is not a Tag:
the Tag is `charlie.Knows`, or `bob.Knows`, each made for its Agent. So
asking whether Ruth is in `Knows` means nothing, and asking whether she
is in Charlie's or in Bob's means something different each time. Every
Tag-level act on the template is refused, and the message points to a
Link:

`del Knows` as a bare Python name deletes a name, not a TOP Tag. The
whole-Field TOP act is `del charlie.Knows[:]`.

```python
try:
    ruth in Social.Knows
except TagCompositionError as error:
    assert "link through an Agent" in str(error)
else:
    raise AssertionError("a Relation has no Field")
```

For the same reason a Relation is never a Tool kind, and never a Pin.

## A Tool or a Link?

Both are things an Agent holds by name. They answer different questions.

| | Tool, `@Tool(Weapon)` | Link, `@Link` |
| --- | --- | --- |
| What it says | Charlie **has** this sword. | Charlie **knows** these people. |
| How many | one held value | a Field of Contacts |
| Held | strongly, under a Record's name | the Contacts weakly, in the Link's Field |
| Checked | the value's kind, at every write | the Relation's gate, at every linking |
| Written on the held one | nothing | membership, and only the lines marked `@Public` |
| Facts about the two | the program's | the Pair's Records |
| The slot | a Record: overlaid, assignable | closed and read-only |

Neither leads back from the held one to its holder.

## Questions to keep separate

| Question | Expression |
| --- | --- |
| Does Charlie know Ruth? | `ruth in charlie.Knows` |
| What is between them? | `charlie.Knows[ruth].since` |
| Does their Pair keep its promises? | `bool(charlie.Knows[ruth])` |
| Which of Charlie's Contacts are sound, Pair included? | `list(charlie.Knows)` |
| Which are not? | `list(~charlie.Knows)` |
| Everyone Charlie knows, sound or not? | `list(charlie.Knows[:])` |
| Does Charlie hold a Link of that name? | `"Knows" @ charlie` |
| Who knows Ruth? | `[a for a in Social[:] if ruth in a.Knows]` |
| Forget her | `del charlie.Knows[ruth]` |
| Forget everyone | `del charlie.Knows[:]` |
