# TopKit: asking about Posts

A Post states a promise about its Agent. Reading `ari.Ready` calculates
that named Post. `bool(ari)` asks whether the Agent is free of Safehouse
arrest and all its visible Posts hold. `Contract.Status(ari)` gives the
individual Post verdicts for diagnosis.

Ordinary Posts belong to their Tagging's membership. They end when the
Agent leaves that Field. An admitted Constant Post remains after Rip,
like an NDA that still applies after leaving an Agency.

## A recursive reference contributes True

While TOP checks a Post, that Post may ask another question that reaches
the very same Agent and Post again. That unfinished reference contributes
the neutral `True`. The surrounding calculation continues, and every
other promise still matters.

```python
from TopKit import Contract, Post, Tag

class Host:
    pass

class Car(Tag):
    @Post
    def Ready(ari):
        return bool(ari)

    @Post
    def Safe(ari):
        return ari.safe

ari = Host()
ari.safe = True
Car(ari)
assert ari.Ready

ari.safe = False
assert not ari.Ready
assert not ari
assert Contract.Status(ari) == {"Ready": False, "Safe": False}
```

The recursive `Ready` reference contributes True, but `Safe` still fails.
There is no shortcut that treats the entire Agent as valid merely because
one of its Posts is already being checked.

The same rule applies through named reads, `bool`, sound population
membership, `Contract.Postconditions` and `Contract.Status`. It also
applies when several Agents refer to one another's Posts.

Neutral True is a rule for an unfinished reference, not a solver for
contradictory conditions. A Post that negates its own unfinished verdict
therefore calculates False. Authors should express the underlying facts
directly rather than rely on cyclic equations to establish a contract.

## One question reuses completed verdicts

Within one complete question, TOP reuses the first completed verdict of
each Agent/Post pair. This includes nested questions and later Posts
reaching the same promise. An unfinished recursive reference is not a
completed verdict and is not saved as one.

Each independent question starts fresh. Two separate `bool(ari)` calls
can therefore give different answers when the facts change between them.
Population length, population truth and combined membership questions
also share verdicts within that one question. A walk still keeps its
usual per-Field timing; this rule does not turn Fields into a snapshot.

This local reuse avoids repeatedly traversing a collective contract.
It does not inspect or freeze arbitrary Python state. Preconditions and
Posts should read facts and call Actions that retrieve or calculate
values. TOP refuses explicit TOP mutations during a check; ordinary
Python writes and I/O remain the author's responsibility.

Python finalization also remains outside that guard: it must be able to
clean up unrelated Agents during a calculation. Explicit `ari.__del__()`
calls follow that same Python finalizer path. Authors must not use them
as a way to change state from a check.

## Credentials still apply

A remembered verdict does not open a Secret door or authorize an arrested
Agent to act. Secret permission probes prevent later reads from reusing
a verdict outside its protected calculation. TOP also checks custody
before accepting a Post answer.

`Contract.Status` remains a diagnostic about the Posts themselves.
An arrested Agent can have a pure Post whose answer is True, while
`bool(ari)` is False because Rip remains unfinished. A Post that needs
to read guarded Agent data still has to obey the ordinary access rules;
asking for Status grants no Rip authority and retries no cleanup.
