# Review: the TOP paradigm, TagKit, and the proposed STEPs

- **Date:** 2026-09-04
- **Reviewed:** `spec/SPECIFICATION.md` (main), `TagKit/TagKit.py` (main, 0.1),
  the `codex/tagkit-0.2-alpha` branch (PR #1), STEP-SPEC-1 / -2 / -3
  (PR #1 and PR #2).
- **Method:** every defect below was reproduced with a script against the
  real code. Every performance figure was measured on Python 3.11 in this
  session. Nothing here is inferred from reading alone.

---

## 1. Verdict in one page

**The paradigm is sound.** One stable identity, membership as the primary
contribution, sticky layers, captured Underlays, tag-time contracts with the
Liskov direction (Forward-Post, Backward-Pre), and atomic taggings form a
coherent, small algebra. The vocabulary is good and the Manifesto boundary,
*"OOP owns inherent structure; TOP owns semantic context"*, is the right
sentence to build on.

**TagKit 0.1 (main) has six real defects**, three of which break the
paradigm's own laws (identity preservation, "no implicit projection",
atomic failure types). All are fixable in a day. Details in §3.

**TagKit 0.2 (PR #1) fixes those six**, but it is a 22,000-line rewrite
that also changes observable semantics in five places without a STEP,
contradicts its own `CONFORMANCE.md`, and makes attribute access ~2.5x
slower than 0.1 (which was already 10x slower than a plain object). It should
not merge as one unit. Details in §4.

**The STEPs:**

| STEP | Verdict | Condition |
| --- | --- | --- |
| SPEC-1 Contribution scope | **Clear** | Record the Vetting/Cleared dates; one wording fix (§5.1). |
| SPEC-2 Tag members composition-internal | **Clear as convention, Redact the runtime gate** | "Inside composition" is not a decidable runtime predicate in Python; keep it a documented law + tooling rule. |
| SPEC-3 Member publication | **Return to Brief** | Two examples are not valid Python; the Operation-adapter rule is underspecified; `@Secret` duplicates the underscore rule the kit already has. |
| Checkpoints (PR #1, no STEP) | **Needs a STEP** | Good idea, but as implemented an Agent is invisible to its own Actions inside an open checkpoint, which breaks the SPEC-1 Agency pattern. |
| Uniform access (PR #1, no STEP) | **Redact** | Violates "explicit before magical"; the proxy object leaks into host code. |
| Defective taggings (PR #1, no STEP) | **Needs a STEP, currently contradicts CONFORMANCE.md** | Reverses "atomic, all-or-nothing". |

## 2. The paradigm (Specification on `main`)

### 2.1 What is strong

- **Membership first.** "An otherwise empty Tag is meaningful" is the
  cleanest statement of what distinguishes TOP from mixins/traits/ECS.
- **Sticky contributions + explicit Rip** gives a precise, defensible answer
  to the Role Object pattern's weakness (roles that vanish without trace).
- **Captured Underlay** (callable composition frozen at tagging time) is a
  genuinely different composition rule from MRO-based `super()`, and the
  `Paladin → Elf` example shows it well.
- **Strict boolean contracts** with the `0 spell slots` argument is exactly
  right and unusual; most contract systems get this wrong.
- **Forward-Post / Backward-Pre with a diagnosed weakening** is the correct
  Liskov reading and the "diagnosed, not forbidden" choice matches the
  paradigm's refactoring goal.

### 2.2 Contradictions inside the spec, and between spec and kit

These are the items a conformance suite cannot be written against until
resolved.

1. **Rip cascade vs Rip refusal.** Spec §Imprinting and Ripping says
   *"Ripping removes the Agent from the Tag's Field and, by default, from
   the Fields of Shapes that depend on that Tag"* (cascade). TagKit refuses:
   `Beast.Rip(wolf)` raises `TagCompositionError: Beast is required by
   active Shape(s): Wolf`. Both branches carry the sentence and both kits
   refuse. Pick one. Recommendation: **refuse** (the kit's behaviour). A
   cascade silently runs other Tags' `@Rip` protocols, which is exactly the
   hidden mutation the Design Patterns section forbids. Then fix the
   sentence.
2. **"Deletion always Rips the Agent."** Python does not guarantee
   finalizers at shutdown or in cycles; `IMPLEMENTATION_NOTES.md` already
   says so. The spec should state the three tiers (`__del__` best-effort,
   `Scope` guaranteed, `At_Exit` opt-in) rather than promise what no Python
   profile can deliver.
3. **Agent-bound view after Rip.** Spec: *"fails with a Tag-resolution
   error."* Kit: `agent.Paladin` raises `AttributeError`;
   `agent.Tag(Paladin)` raises `TagResolutionError`. The `AttributeError` is
   right for Python (`hasattr` must work); the spec should say "a
   Tag-resolution failure, or the language's attribute-missing failure".
4. **Duplicate sections.** "🔩 Contributions" appears twice (lines 199 and
   340), the tag-time sequence appears twice (Imprints §, Conditions §), and
   the failure table appears twice. Merge them. Duplicated normative text
   drifts; it already has (one says "Preconditions... before Imprints", the
   other defines a five-step order).
5. **Example errors.** The mental-model example defines `Hero` but asserts
   `isinstance(charlie, Character)`; its output prints "wizard" for a Tag
   named `Wizard`. Small, but this is the first code a reader sees.
6. **`Contract.Display` output shows `Hero__Wizard`.** That is TagKit's
   synthesized type name, an implementation detail, in the normative text.
7. **"crunch"** is used as a verb in three places and is not in the
   vocabulary table.

### 2.3 Gaps the spec should close

- **Define "identity".** The spec promises "stable identity" but Python's
  `type(agent)` changes on the first tagging (`type(h) is Hero` becomes
  `False`; `h.__class__.__name__` becomes `Hero__Squire`). Say precisely:
  object identity (`is`, `id`, hash, equality) is preserved; nominal type
  identity may be wrapped; code that keys on `type(x) is Host` is outside
  the guarantee.
- **Inputs to conditions of earlier Tags.** "Every visible condition runs"
  at each boundary, but conditions may take application inputs. On `main`
  this is a trap (see §3, A): a Precondition declared with `code` re-runs on
  every later, unrelated tagging with `code=None` and fails. 0.2 fixed it by
  making Preconditions gate only the current call. That is the right rule
  and it needs to be in the spec, not just the changelog.
- **Shared mutable Tag state.** The `Secret_Agent.active_agents += 1`
  example works, but it silently replaces the `Report` wrapper on the class
  with a bare `int`. Either say Reports are immutable values and mutable
  shared state belongs in an Operation-guarded container, or give Reports a
  write path.
- **Records over host descriptors** (a `@property` with no setter) are
  undefined. Both kits raise a raw `AttributeError`, not a TOP failure.
- **Thread-safety** is unaddressed while the spec lists "permissions" as a
  target domain. One sentence ("one Agent, one thread; Fields are not
  synchronised") is enough for now.
- **Warn on independent Record replacement.** The spec asks for a
  diagnostic when an independent Tag replaces an Action. Records get none
  in either kit, yet a replaced Record is the more dangerous case (state,
  not behaviour). Extend the rule to Records.

## 3. TagKit 0.1 (`main`)

58 tests pass. The code reads well: one step per line, named helpers,
weak everything. The following were reproduced with a probe script; letters
refer to that script.

### 3.1 Defects (ordered by severity)

| # | Finding | Evidence | Law broken |
| --- | --- | --- | --- |
| **C** | `Tagged` is placed *before* the host in the runtime MRO, so its `__contains__`, `__bool__`, `__or__`, `__ior__` **shadow the host's**. A host container's `'x' in bag` flips from `True` to `False` after tagging; `bag \| 1` raises `TypeError: 1 is not a Tag class`; an empty collection becomes truthy. | probe C | Stable identity under tagging |
| **B** | Tag classes are in the runtime MRO, so **Tag-level members leak onto the Agent**: `agent.colour` returns the raw `Report` object (not its value), `agent.Greet("x")` calls the Operation with the runtime type as receiver, `agent.Label()`, `agent.NAME`, `agent.Lineage()` all resolve. Any host method named `Label`/`Path`/`Describe` is shadowed. | probe B | No implicit projection; Tag scope ≠ Agent scope |
| **A** | A Precondition that declares an application input (`Has_Code(agent, code)`) is re-evaluated on **every later tagging** with `code=None`, so `Coded(h, code="x"); Plain(h)` raises `TagPreconditionError`. | probe A | Preconditions are gates for *this* tagging |
| **H** | A teardown marked `@Rip @Underlay` crashes on Rip with a raw `TypeError` (the raw declaration is called without its Underlay). | probe H | Defined failure types |
| **M** | A Record over a host `@property` without a setter raises raw `AttributeError`. Rollback is correct, the failure type is not. | probe M2 | Defined failure types |
| **R** | A `TypeError` raised *inside* a Record builder is reported as *"Hero cannot be actualized in place"* because the `except TypeError` branch in `_apply_one` is too wide. | probe R | Diagnostics must name the violated rule |

Smaller: `Squire()` with no target silently constructs a meaningless Tag
instance (probe G); `type(agent).__name__`, `AppliedTags()`, and
`Contract.Display` stay stale after Rip because Rip never rebuilds the
runtime type (probe D); `TagDeletionError` and `Tag.ABSTRACT` are declared
and never used; `_exit_registry` keeps dead weakrefs forever (1000 entries,
0 live, probe Q); `warnings.warn(stacklevel=3/4)` are guesses that point
into the kit after any refactor.

### 3.2 Root cause and the one structural fix

Defects **B**, **C**, and **D** share a cause: **Tags and `Tagged` are put
into the Agent's MRO** to make `isinstance` work. But `isinstance` is
*already* answered by `MetaTag.__instancecheck__` via `ever_tags`. The MRO
membership buys nothing and costs identity.

Recommendation: the runtime type should be `(Tagged, host)` only, with
`Tagged` **after** the host for everything except `__getattribute__`,
`__getattr__`, `__del__` (which must intercept). Concretely:

- build the runtime type as `type(name, (host, _TopHooks), namespace)`
  where `_TopHooks` carries only the three hooks and the namespace carries
  dunder Actions;
- drop `__or__`, `__ior__`, `__contains__`, `With`, `As`, `ApplyTags` from
  the mixin (0.2 already moved these to `Apply`/`Has`/`Tags` functions,
  which is the right call: sugar on the Agent competes with the host);
- make `__bool__` conditional: install it only when the composition has a
  visible Postcondition (0.2 does this).

Then the shared-type cache key is just `(host, dunder-signature)`, so far
more Agents share one type, and B/C/D disappear together.

### 3.4 Design choices worth reopening

- **Function defaults are ignored for protocol inputs** (`def SetUp(agent,
  code="unknown")` receives `None`, probe L). "The call is the single source
  of truth" is a defensible rule, but it contradicts how every Python reader
  reads a default. Recommend: honour the default when the caller omits the
  input; keep `None` only for parameters with no default.
- **`__bool__` runs all Postconditions.** Every `if agent:`, `agent or
  default`, `filter(None, agents)` in host code now runs contract checks
  (1.9 µs each on 0.2). The spelling is elegant; the cost is invisible.
  At minimum, document it under performance; consider `Contract.Holds(agent)`
  as the canonical form and `__bool__` as the sugar.
- **Rip + reapply resets Records** (`rank` goes back to `"squire"`, probe
  O). Reasonable, but undocumented; say it.
- **`copy.copy(agent)` shares one `_TAGKIT_STATE` object** between the copy
  and the original, so tagging one mutates the other's state (probe N).
  Either define `__copy__` to deep-copy the state or raise. 0.2 documents
  "define cloning in your domain", which is fine, but the kit should not
  silently alias.

## 4. TagKit 0.2 alpha (PR #1)

197 tests pass (`-X dev`), stress suite 24 tests in 13 s.

### 4.1 What it gets right

- **Neutral runtime types** (Tagged + host only). Fixes B, C, D from §3.
- **Preconditions gate only the current call.** Fixes A.
- **Identity-indexed Fields.** Fixes E.
- **`ContextVar` re-entrancy guards** instead of a global `set[int]`.
- **`Apply` / `Has` / `Tags` as functions**, not Agent methods.
- **Removing `NAME` / `DESCRIPTION` / `ABSTRACT` / `Label()`.** The
  Manifesto's "a Tag primitive should not invent application data" is
  correct and this follows it.
- Rip teardown failures are wrapped (`TagCompositionError`), not raw.
- The stress suites and `STRESS_TESTING.md` are a real asset.

### 4.2 What it gets wrong

1. **Size and shape.** 10,000 lines of kit for a paradigm whose Design
   Patterns section says "clear before clever". `runtime_types.py` is
   2,196 lines with a 644-line `Tagged` class and a 116-line
   `__getattribute__`. `access.py` has a 400-line `_Bound_Member` proxy
   whose only job is the uniform-access sugar. `transactions.py` is 1,402
   lines. By the author's own rule, "smart code is not maintainable", this
   is the kind of code the rule warns about. The module split is good; the
   modules themselves are not small.
2. **Attribute access got 2.5x slower than 0.1** (925 ns vs 367 ns for a
   plain host attribute read; an Action call went from 917 ns to 2,610 ns;
   `bool(agent)` is 1,890 ns). The cause is visible in `__getattribute__`:
   after the TOP lookups it re-resolves the host's `__getattribute__` and
   compares bound members on *every* host-attribute read. Host attribute
   reads are the common case and must be the fast path: one dict miss, then
   `object.__getattribute__`.
3. **Uniform access is a proxy, not a value.** `agent.hp` is a
   `_Bound_Member`, not `30`: `isinstance(agent.hp, int)` is `False`,
   `json.dumps(agent.hp)` raises, `agent.hp is None` can never be true, a
   plain function receiving `agent.hp` gets the proxy. `agent.Say` prints as
   a bound method but compares equal to `"hi"`. The profile doc admits the
   leak ("use `()` when Python needs the raw object"). This fails "explicit
   before magical" and "no hacks, no magic" outright. A Record should be a
   value; an Action should be a callable. Recommend removing it; the
   Polymorphic-behaviour goal (a Shape turning an Action into a Record) is
   achievable without it: the Overlay just changes kind, and the client
   writes the kind it sees.
4. **"Defective taggings" reverse atomicity without a STEP.** On 0.2 a
   failed Postcondition or Imprint **keeps the Tag applied** (`h in Wiz` is
   `True` after `TagPostconditionError`; a failing Shape also leaves its
   Base and Records committed). `CONFORMANCE.md` on the *same branch* still
   says "atomic taggings, all-or-nothing, with no partial commits". The
   factory analogy (a factory does not unmake an unsafe toy) is a good
   argument, and `~Tag[:]` (the defective population) is a genuinely useful
   query. But this is the single largest semantic change in the project's
   history and it lives in a commit titled "Add uniform access, condition
   Agent members, and Field algebra". It needs its own STEP and a decision.
5. **Default Field iteration hides members.** `for a in Tag` iterates only
   the *sound* population. Combined with (4), an Agent can be a member, be
   invisible to `for a in Tag`, and be visible to `agent in Tag`. That is a
   surprising partition for the most basic loop in the paradigm. Recommend:
   default iteration = the whole Field; `Tag[:]` and `~Tag[:]` are the
   explicit partitions.
6. **Exception subclasses are minted for any name.**
   `TagPostconditionError.Typo_Name` returns a fresh exception class, so
   `except TagPostconditionError.Has_Spelbook:` compiles, runs, and never
   catches anything. This is a silent-failure generator. If named exceptions
   stay, they must be created only for declared condition names and raise
   `AttributeError` otherwise.
7. **`ImprintingError` and `TagImprintError` both exist** with different
   meanings. One name per concept.

### 4.3 Recommendation for PR #1

Do not merge as one PR. Split, in this order, each mergeable alone:

1. Module split + neutral runtime types + identity-indexed Fields +
   ContextVar guards + Pre-gates-current-call (pure fixes, no STEP needed,
   they *implement* the existing spec better).
2. `Apply` / `Has` / `Tags` and removal of Agent sugar (small STEP or
   changelog entry; it changes the surface).
3. Checkpoints (STEP, see §5.4).
4. Defective taggings + Field algebra (STEP, see §5.5).
5. Uniform access + condition Agent members (STEP; my recommendation is
   Redact).

## 5. The STEPs

### 5.1 STEP-SPEC-1, Contribution scope follows the receiver — **Clear**

This is the right law and it is well argued. `(scope, name)` as the
Overlay coordinate, separate contract phases, no implicit Operation
projection, and the Agency pattern (guarded Operation checking membership
at invocation, so a captured `send` fails closed after Rip) are all
correct and the acceptance list is testable.

Two notes before Deployed:

- The status jumped from Brief to Deployed on 2026-09-02 in an unmerged
  branch. The process says Vetting → Cleared → Deployed, each recorded.
  Backfill the dates so the first STEP on the record models the process.
- "Independent Tags cannot place an Action and a Record at the same Agent
  coordinate… fail atomically" is good. Add the diagnostic rule for the
  *same-kind* independent case (Record replacing Record), which the spec
  currently only states for Actions (§2.3).

### 5.2 STEP-SPEC-2, Tag members are composition-internal — **Clear as a law, Redact the runtime gate**

The organizing idea is right: the Tag's public footprint is its Field;
Tag-scoped members are reached through a carried layer or an Action
adapter. As a documented law and a tooling rule it should be Cleared.

The optional runtime enforcement should be dropped, for three reasons:

- **"Inside composition" is not a decidable predicate at runtime.** The
  STEP defines the door dynamically (a call made while an Action, Imprint,
  Record materializer, Condition, or Rip of *this* Agent is executing). In
  Python that means a `ContextVar` set on every Action entry and checked on
  every Tag-member access, and it leaks through callbacks, generators,
  `asyncio` tasks, threads, and any handle captured inside and called
  outside. Every Action call pays for it.
- **Motivation 2 is not delivered by the mechanism.** The STEP says
  `agent.Fire.color` "supports parallel definitions and modded
  compositions without a single global Fire singleton". But the view is
  resolved **by class name** (`tag.__name__ == "Fire"`), so two Tags named
  `Fire` from different mods collide on `agent.Fire`; last-applied wins.
  Only `Fire[agent]` (by class object) is robust. The STEP should say so
  and prefer the class-keyed spelling.
- The Manifesto says TOP "does not require a framework to reinterpret
  ordinary code". A runtime visibility gate is exactly that.

### 5.3 STEP-SPEC-3, Member publication — **Return to Brief**

The two-axis model, scope × publication, is a clean idea and the
defaults table is right. But the STEP is not ready for Vetting:

1. **Two reference examples are not valid Python.**
   `@Public` followed by `color = "#ef5b35"` is a `SyntaxError`; decorators
   apply to `def`/`class` only. It must be `color = Public("#ef5b35")` or
   `color = Public(Report(...))`. The STEP's own reference spelling has to
   run.
2. **The Operation adapter rule is undecidable as written.** "If the
   Operation concerns one Agent, the Action passes that Agent as an
   explicit input." Nothing in a signature says whether an Operation
   "concerns one Agent". State a mechanical rule: the published Action
   always passes the Agent as the Operation's second positional argument,
   or never does and the author writes the adapter.
3. **`@Secret` duplicates an existing rule.** TagKit already excludes
   underscore-prefixed names from declarations entirely (`_is_private`),
   which is Python's native "internal" spelling and the Manifesto's
   "language profiles should feel native". `@Secret` adds a second way to
   say the same thing, plus a runtime gate with the SPEC-2 problems above.
   Recommend: `@Secret` is defined as "internal by publication" with
   declaration-time meaning only (excluded from `agent.name` flat access,
   still reachable inside the Tag's own bodies via a class-keyed view);
   the underscore prefix is the Python profile's spelling of it.
4. **`@Public` Report → nullary Action depends on uniform access** ("read
   as `agent.color` or `agent.color()`"). If uniform access is Redacted
   (§4.2), a published Report should be a read-only Record alias, which
   the STEP lists as "set aside" for the wrong reason.
5. One STEP, one topic: this STEP introduces *two* marks with different
   receivers and different mechanics. Split `@Public` (adapter generation,
   Tag-scoped) from `@Secret` (visibility, Agent-scoped).

### 5.4 Checkpoints (PR #1, no STEP) — **Needs a STEP; fix the visibility rule first**

A recoverable multi-Tag design phase is a real need (generated builds,
try-then-approve). The API (`Tag.Checkpoint(target)`, `Commit`, `Restore`,
context-manager form, Rip forbidden while open) is clean.

The current semantics have one flaw that must be decided before it is
specified: **inside an open checkpoint the Agent is not a member of the
Tags applied in it.** `Wizard(h)` then `h in Wizard` is `False`,
`isinstance` is `False`, an Imprint that checks `agent in Needs` sees
`False`, and the SPEC-1 Agency pattern raises `PermissionError` on
`agent.broadcast()` until `Commit`. So the code most likely to run inside a
checkpoint (Actions and Imprints of the Tags being tried) sees a world in
which the tagging did not happen. Either:

- membership is visible to the Agent's own protocols during the phase and
  only *Field publication* (iteration by outsiders) is deferred, or
- the STEP states plainly that a checkpoint is a *dry run* in which
  membership-guarded behaviour cannot be exercised.

The first is the useful one. It also matches the 0.2 notes' own
"commit-only observation" wording better than the current behaviour.

### 5.5 Defective taggings and Field algebra (PR #1, no STEP) — **Needs a STEP**

`Tag[:]` / `~Tag[:]` / U-set is a good, small algebra and reads well.
Keeping a Tag applied after a failed Post is the contested half. Write the
STEP with both options and their consequences on `CONFORMANCE.md`:

- **Keep atomic** (current spec + 0.1): simpler law, no invisible members,
  no defective population; a failed Post means "try again".
- **Defective result** (0.2): richer diagnostics, matches the factory
  analogy, but every consumer of a Field must now decide sound vs all, and
  `bool(agent)` becomes load-bearing.

If the second wins, default iteration must be the whole Field (§4.2 item 5)
and `CONFORMANCE.md` must change in the same PR.

### 5.6 Uniform access and condition Agent members (PR #1, no STEP) — **Redact**

See §4.2 items 3 and 6. The proxy leaks into host code, the
named-exception factory swallows typos, and both exist to save two
characters (`()`). `agent.Has_Spellbook` as a readable boolean is nice;
`Contract.Status(agent)["Has_Spellbook"]` already provides it without a
new member kind that "cannot share an Agent name with an Action or Record".

## 7. Suggested order of work

1. **Fix `main` in place** (a day): neutral runtime type (§3.2),
   identity-indexed Field (prototype ready, §3.3), Pre-gates-current-call,
   wrap H/M/R failures, prune `_exit_registry`, drop the dead names. Tag it
   0.1.1. This gives a correct, small reference kit *now*.
2. **Resolve the four spec contradictions** (§2.2 items 1–4) in one
   editorial STEP-SPEC-4, with no semantic change.
3. **Clear SPEC-1 properly** (dates), **Clear SPEC-2 as law without the
   runtime gate**, **return SPEC-3 to Brief** with the fixes in §5.3.
4. **Split PR #1** (§4.3). Land the pure fixes; write STEPs for Checkpoints
   and Defective taggings; Redact uniform access.
5. Only then decide whether the 0.2 module layout becomes the base for
   0.2.0. If it does, set a budget: no module over 600 lines, no function
   over 60, and a hot-path benchmark in CI (`agent.attr`, `agent.Action()`,
   `Tag(agent)` at 10k Agents) so the next optimization pass has a baseline.
